WHAT THIS IS
------------
First JEPA-based self-supervised speech model for Kazakh language.
Adaptation of Audio-JEPA (Tuncay et al., ICME 2025) to KSC2 dataset.
Originally targeted arxiv preprint; current focus shifted to
LinkedIn post + HuggingFace upload (preprint optional later).

KEY RESULTS (so far)
--------------------
Domain classification (5-class test, KSC2 source labels):
  Random baseline (1/5):        20.0%
  kNN method:
    Random init encoder:        45.2%
    Old-config 30k:             55.4%   (+10.2 pp over random init)
    Paper-config 2 epochs:      60.8%   (+15.6 pp)
  MLP probe method:
    Random init encoder:        63.0%
    Old-config 30k:             71.8%   (+8.8 pp)
    Old-config 100k:            71.8%   (no improvement — plateau)
    Paper-config 2 epochs:      77.4%   (+14.4 pp)
    Paper-config ~5k step:      77.8%   (+14.8 pp)

Content similarity correlation (label-free):
    Paper-config: Pearson 0.031 (weak, but buckets monotonic)
    → encoder captures acoustic structure, NOT lexical content.
    Known limitation of mel-spec JEPA.

ASR (CTC fine-tuning): DOES NOT WORK
    Reason: patch grid temporal resolution too coarse.
    Old config: 32 time patches; new paper config: 16 patches.
    Median Kazakh transcript = 74 chars → physically can't represent.
    Plateau loss ~3.0, HYP outputs become "ааа нан а" noise.

DECISIONS LOGGED
----------------
- Stick with Audio-JEPA fork — minimal-change adaptation, NOT rewrite.
- ASR formally abandoned for v1: needs Conv1D upsampling head or
  seq2seq decoder (1-3 days more work). Left as future work.
- Domain classification is the primary evaluation, with the caveat
  that radio is too easily separable (broadcast acoustics).
- Paper-config (128×256 mel, batch 256 effective) significantly
  outperforms our initial config — this is the configuration we
  should use for the released checkpoint.
- LinkedIn post + HuggingFace upload chosen as the IMMEDIATE
  publication artifact. Preprint deferred (maybe never, that's fine).

ENVIRONMENT-SPECIFIC GOTCHAS
----------------------------
On Mac (CPU, testing):
  uv sync --no-install-package flash-attn
  PROJECT_ROOT=$PWD uv run --no-sync python src/train.py ...

On RunPod / WSL2 with RTX 5090:
  - PyTorch CUDA 12.8 for Blackwell sm_120:
    pip install --upgrade torch torchvision torchaudio \
      --index-url https://download.pytorch.org/whl/cu128
  - flash-attn skip OK, shim handles it
  - Always pass `test=False` to src/train.py (no test_step in JEPAModule)
  - PROJECT_ROOT=$PWD env var required (referenced in paths config)
  - Paste long commands as ONE LINE — terminal breaks silently
  - For grad accumulation, use `+trainer.accumulate_grad_batches=4`
    (the `+` is required — key isn't in default trainer config)
  - Lightning's RichProgressBar doesn't flush to nohup log file —
    monitor via checkpoint timestamps instead.

COMMANDS REFERENCE
------------------
Convert data:
  PROJECT_ROOT=$PWD python convert_to_hdf5.py \
      --src /path/to/ISSAI_KSC2 --out data/KSC2

Pretrain (paper-exact config, ~21 hours for 100k steps on 5090):
  PROJECT_ROOT=$PWD nohup python src/train.py data=ksc2 trainer=gpu \
      trainer.max_steps=100000 data.batch_size=64 \
      +trainer.accumulate_grad_batches=4 \
      data.num_workers=8 tags='[paper_config,100k]' test=False \
      > training_paper_cfg.log 2>&1 &

Build manifest + vocab:
  python prepare_ksc2_asr.py --src /path/to/ISSAI_KSC2
  python asr_data.py build-vocab --manifest data/KSC2/asr_manifest.csv

Eval (note: --mel-bands and --mel-time must match the checkpoint's
training config; default 128×256 for paper-config checkpoints,
pass --mel-bands 96 --mel-time 512 for old-config checkpoints):
  python evaluate_knn.py    --ckpt <ckpt> --per-domain-train 500 --per-domain-test 100
  python linear_probe.py    --ckpt <ckpt> --per-domain-train 500 --per-domain-test 100
  python evaluate_content_similarity.py --ckpt <ckpt> --n-clips 1000 --n-pairs 5000
  python visualize_embeddings.py --ckpt <ckpt> --tag mymodel
  python quick_test_jepa.py --ckpt <ckpt>

Random-init baselines (same scripts, --random-init flag):
  python evaluate_knn.py --random-init ...
  python linear_probe.py --random-init ...

ANTI-PATTERNS — DO NOT REPEAT
-----------------------------
- Don't claim the result is more impressive than it is.
  The +14 pp gain on domain classification is real but modest;
  radio dominates the easy-task side. Be honest in any paper/post.
- Don't suggest more pretraining as a fix — we proved it doesn't
  help past ~30k for the same config. Architecture is the bottleneck,
  not compute.
- Don't push for ASR with the current encoder — temporal resolution
  is wrong for CTC. Would need a real architectural fix.
